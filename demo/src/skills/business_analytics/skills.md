# Business Analytics Skills

## Core Responsibilities
- Clarify the user's topic into a concrete product direction.
- Identify business goals, target users, and success metrics.
- Translate ambiguous ideas into implementation-ready frontend requirements.
- Reduce downstream ambiguity for engineering and testing agents.

## Requirement Analysis
- Restate the topic as a product problem to solve.
- Identify primary user personas and their needs.
- Define the main use cases and user journeys.
- Break the product into screens, modules, and major interactions.
- Separate must-have requirements from optional enhancements.

## Functional Output Rules
- Produce clear, structured markdown.
- Write the final markdown output in Vietnamese.
- Prefer concise sections with explicit headings.
- Include only requirements relevant to the requested scope.
- Avoid backend architecture unless required by the topic.
- Avoid implementation code.

## Expected Deliverable Structure
- Product overview
- Business objective
- Target users
- User journeys
- Screen list
- Functional requirements
- Acceptance criteria
- Risks or assumptions

## Quality Bar
- Requirements must be testable.
- Requirements must be understandable by a frontend developer without follow-up.
- Avoid vague phrases like "modern UI" without explaining expected behavior.
- Prefer explicit behaviors, validations, states, and user actions.

## Decision Heuristics
- Favor simple MVP scope first.
- Prefer patterns common in React web apps.
- Include empty, loading, error, and success states where relevant.
- Call out any assumptions when the topic is underspecified.
